ICMP — Ping & Traceroute Mechanics

Not TCP (Transmission Control Protocol), not UDP (User Datagram Protocol), no port numbers at all. ICMP is the network's own diagnostic and error-reporting channel, and it's the entire mechanism behind two of the most-used tools in networking.

What ICMP actually is

ICMP (Internet Control Message Protocol) rides directly inside IP (Internet Protocol; Protocol number 1, from the IPv4 header topic) rather than on top of TCP or UDP. It has no ports, no sessions, nothing to connect to. It exists purely to carry short, structured control and error messages between devices. Every ICMP message has a type and code that say exactly what it's reporting.

Ping: echo request and reply

Ping is the simplest possible use of ICMP: send a type 8, Echo Request, and if the destination is reachable and willing to answer, it sends back a type 0, Echo Reply. No data exchanged beyond "are you there," and how long the round trip took.

Traceroute: abusing TTL on purpose

Recall from the IPv4 header topic that every router decrements a packet's TTL (Time to Live) by one, and drops it with a type 11, Time Exceeded message if TTL hits zero. Traceroute turns that error condition into a mapping tool: it sends a packet with TTL=1, which dies at the very first router, revealing that router's address in the Time Exceeded reply. Then it sends one with TTL=2, which dies at the second router. It keeps incrementing until a packet finally survives all the way to the destination.

Each router's Time Exceeded reply comes from that router's own address, so by the time a probe finally survives to the destination, traceroute has assembled the full list of routers in between, one hop revealed per probe.

ICMP types and codes, in full

Every ICMP message carries both fields: type says the general category, code narrows it down within that category. Some types only ever have one code; others, like Destination Unreachable, use the code to say exactly why the packet couldn't be delivered.

A NO-REPLY DOESN'T MEAN A DEAD HOST

Firewalls very commonly block ICMP outright as a hardening measure, since it can also be used to probe or map a network. A host that never replies to ping might be perfectly reachable on every port that actually matters. Treat "no ping" as "ICMP is filtered," not proof the host is down.
