Static Routing

The simplest possible way to tell a router how to reach a network: just tell it. No protocol, no negotiation, no automatic adaptation either.

What a static route actually is

A static route is an administrator manually entering a destination network and how to reach it, either a next-hop IP address or an outgoing interface. That's the entire mechanism: no protocol runs in the background, no negotiation with neighboring routers, nothing gets learned automatically.

Where it's the right tool

  • Small networks with few routers and paths that basically never change.
  • A default route pointing a stub network's only exit toward its single upstream connection.
  • Point-to-point links where there's only ever one possible path anyway, so a dynamic protocol has nothing to compute.

Where it falls apart

Static routes don't adapt. If the configured next-hop goes down, the route stays in the table (unless the router also loses reachability to the next-hop itself) and traffic keeps getting sent into a dead end until a human notices and fixes it. And every network has to be entered by hand, on every router that needs to reach it — a topology with dozens of routers becomes an enormous, error-prone amount of manual configuration. That's exactly the problem the dynamic routing protocols later in this module exist to solve.

THE ONE PLACE STATIC ROUTES SHINE EVEN IN A DYNAMIC NETWORK

The floating static route from the previous topic: configured with a deliberately higher administrative distance than whatever dynamic protocol is running, sitting completely unused until the dynamic route disappears, then taking over automatically as a backup. It gets the reliability of a dynamic network with the predictability of a static one, exactly where you need it.
