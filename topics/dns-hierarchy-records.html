DNS Hierarchy & Record Types

DNS (Domain Name System) is organized as a delegated tree, not one giant lookup table, and different record types on the same name answer completely different questions.

A tree, not a flat list

DNS is structured like a global franchise business, not a single company you could look up in one place. The root level is like a headquarters: it doesn't know where "example.com" actually lives, but it knows exactly which regional office handles everything ending in .com. That regional office, a TLD (Top-Level Domain) server, doesn't know example.com's content either, but it knows which specific store location, the authoritative server for example.com, is licensed to answer for it. And that store can run its own departments, subdomains like www.example.com or mail.example.com, all still under the same license.

Record types: different questions, different answers

A single name like example.com can have several different kinds of records, each answering a completely different question.

RecordFull nameAnswers
AAddressWhich IPv4 address does this name point to?
AAAANicknamed "quad-A": four times the size of an A recordWhich IPv6 address does this name point to?
CNAMECanonical NameWhat's the "real" name this is just an alias for?
MXMail ExchangeWhich server handles email for this domain, and in what priority order?
NSName ServerWhich servers are authoritative for this zone?
TXTTextArbitrary text, commonly used for domain ownership verification, SPF/DKIM email policy
SOAStart of AuthorityThe zone's master record: primary name server, admin contact, and cache refresh timers
PTRPointerReverse lookup: which name does this IP address belong to?

Why delegation matters

Nobody has to ask a single central server for every name on the internet, and nobody needs the root's permission every time a subdomain changes. The owner of example.com can add, change, or remove www.example.com and mail.example.com freely on their own authoritative server, since the root and the .com TLD only delegated authority for the zone, not control over what's inside it. That's what lets DNS scale to billions of names without a single bottleneck.

WHY TTL MATTERS ON EVERY RECORD

Every record carries its own TTL (Time to Live), how long a resolver is allowed to cache it before asking again. A short TTL means changes propagate fast but generates more lookup traffic; a long TTL means less load but slower failover if something changes. How resolvers actually use that cached answer is the next topic.
